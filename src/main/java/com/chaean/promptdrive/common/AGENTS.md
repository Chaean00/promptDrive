# common 모듈 작업 지침

루트 `AGENTS.md`의 공통 지침을 우선 적용하며, 이 문서는 `common` 모듈에만 추가로 적용합니다.

## 책임 범위

- 여러 기능 모듈에서 함께 사용하는 기술 공통 요소만 둡니다.
- 공통 응답, 전역 오류 처리, 보안 설정, 영속성 기반 클래스처럼 모듈 간 공통 인프라를 관리합니다.
- member, prompt 등 특정 기능의 Entity, Repository, Service, 도메인 규칙은 이 모듈에 추가하지 않습니다.

## 폴더 역할

- `api`: 여러 모듈이 함께 사용해야 하는 기술 공통 계약만 둡니다. 기능 도메인 계약은 각 기능 모듈의 `/api`에 둡니다.
- `config`: Spring Bean, 보안, 환경 설정 등 애플리케이션 조립을 담당합니다.
- `persistence`: 모든 모듈에서 재사용하는 영속성 기반 클래스와 공통 JPA 설정을 둡니다.
- `web`: 공통 HTTP 응답, 전역 예외 처리, 요청 처리 기반 요소를 둡니다.
- `adapter`: 외부 기술을 공통으로 연결해야 할 때만 둡니다. 특정 도메인 외부 연동은 해당 도메인의 `internal/adapter`에 둡니다.

기능별 비즈니스 로직은 `common`의 어떤 폴더에도 두지 않습니다.

## 의존성 규칙

- 기능 모듈의 `internal` 패키지를 import하지 않습니다.
- 모듈 간 통신이 필요하면 상대 모듈의 `/api`에 공개된 Facade와 DTO만 사용합니다. 상대 모듈의 `internal` 구현을 직접 import하지 않습니다.
- `/api`에는 안정적인 외부 계약만 두고, 구현체·Entity·Repository는 두지 않습니다.
- 공통 코드가 특정 기능 모듈을 알아야 한다면 먼저 공개 계약이나 설정 경계를 검토합니다.
- 공통 변경은 여러 모듈의 HTTP·이벤트 계약에 영향을 줄 수 있으므로 영향 범위를 확인합니다.

## 구현 규칙

- 전역 예외 처리는 기존 `BusinessException`과 공통 `ErrorCode` 체계를 우선 사용합니다.
- 응답 DTO는 공통 응답 계약에 필요한 경우에만 추가하고, 기능별 응답 변환을 공통 모듈로 옮기지 않습니다.
- 환경 설정은 관련 값을 `@ConfigurationProperties`로 묶고 시크릿은 환경 변수로 주입합니다.
- 기술 공통 코드의 변경에는 영향을 받는 외부 경계 테스트를 우선 추가하거나 갱신합니다.
